# PRD.md — AI Learning Radar 產品需求文件

## 1. 產品概述

AI Learning Radar 是一個面向中文學習者的教學內容雷達系統。第一版聚焦 YouTube 中文人工智慧教學影片，系統每天自動搜尋、篩選、評分、摘要、標籤化，並在公開 Dashboard 上呈現每日 Top 20 教學影片。管理者可在後台調整搜尋參數、主題、關鍵字、排除關鍵字、推薦頻道、黑名單頻道、模型設定與排程設定。

產品定位不是「單支影片摘要工具」，而是「YouTube Daily Digest Agent + Learning Dashboard」。它的核心價值是幫學員從大量新影片中快速找到值得學習的內容，並透過 AI 摘要、學習目標、測驗與學習指引降低學習門檻。

## 2. 目標使用者

### 2.1 主要使用者

- 台灣學員。
- 中華電信學院員工或內部學習者。
- 對人工智慧主題有學習需求，但時間有限，需要快速掌握值得觀看的教學影片。
- 第一版不要求登入即可瀏覽與作答。

### 2.2 管理者

- 企業培訓師、課程管理者、內容策展人。
- 需要調整主題、關鍵字、搜尋門檻、推薦頻道、排除頻道、模型與排程。
- 需要手動新增、編輯、刪除、置頂、調整排序影片與文章。

## 3. 產品目標

### 3.1 MVP 目標

1. 每天依主題自動搜尋 YouTube 中文教學影片。
2. 預設主題為人工智慧，後台可新增其他主題。
3. 影片篩選條件：中文、繁體中文字幕優先、簡體中文字幕可接受、排除 Shorts、長度 5 到 120 分鐘、發布時間預設 3 個月內。
4. 每個主題每天抓取 50 則候選影片，去重、評分後選出 Top 20 顯示於首頁。
5. 所有列入排名範圍的影片都存入歷史資料庫。
6. 每支影片產生 AI 摘要、適合對象、學習目標、關鍵概念、教學影片判斷、入門難度判斷與 3 題單選題。
7. 公開 Dashboard 支援篩選與搜尋。
8. 詳情頁展示完整摘要、測驗、metadata、transcript 摘要。
9. 管理後台支援多管理員、參數調整、手動內容管理、run log 與模型設定。
10. 第一版不儲存一般使用者作答紀錄。

### 3.2 非目標

第一版不做以下功能：

- 一般使用者帳號、個人化推薦、收藏、稍後觀看、看過標記。
- 使用者作答紀錄、答對率統計、學習歷程分析。
- Bilibili、RSS、文章自動納入正式流程。
- 無字幕影片的 Whisper 轉錄。
- 影片播放器嵌入；第一版只連回 YouTube。
- 管理者事前審核流程；AI 自動發布，但管理者可事後調整。

## 4. 產品名稱

正式名稱：AI Learning Radar

備註：原暫稱 YouTube 3D 容易被誤解為 3D 影片或視覺效果。AI Learning Radar 更能表達「學習內容雷達」的定位，也能容納未來文章、RSS、Bilibili 與手動內容來源。

## 5. 內容範圍

### 5.1 第一版內容來源

- YouTube。

- 使用者主要位於台灣。

## 7. 搜尋策略

### 7.1 每日搜尋

- 每個啟用主題每天搜尋一次。
- 每個主題預設取 50 則候選影片。
- 若某主題候選影片不足 10 則，全部進入當日候選清單。
- 搜尋區間預設為最近 3 個月，管理者可調整。
- 搜尋語言為中文，允許英文技術詞。
- 若使用者或管理者輸入台灣常用字，系統可在背景展開為中國常用字搜尋一次。

### 7.2 Query expansion 範例

輸入：「人工智慧入門」

可展開：

- 人工智慧 入門 教學
- 人工智能 入门 教程
- AI 入門 教學
- AI 零基礎 教學
- AI 零基础 教程
- 生成式 AI 入門
- Generative AI 中文 教學

輸入：「LLM」

可展開：

- LLM 中文 教學
- 大型語言模型 教學
- 大语言模型 教程
- Large Language Model 中文 入門

## 8. 影片篩選條件

### 8.1 基本條件

| 條件 | 預設值 | 可由後台調整 |
|---|---:|---|
| 發布時間範圍 | 最近 90 天 | 是 |
| 影片長度 | 5 到 120 分鐘 | 是 |
| 是否排除 Shorts | 是 | 是 |
| 語言 | 中文 | 是 |
| 字幕 | 繁中優先，簡中可接受 | 是 |
| 最低觀看數 | 0 | 是 |
| 最低參與度分數 | 0.05，預設作為加權/門檻參數 | 是 |
| 每主題候選數 | 50 | 是 |
| 每主題首頁上限 | 20 | 是 |

### 8.2 不以最低觀看數淘汰新影片

第一版不使用絕對最低觀看數作為硬性淘汰條件，避免新上架但品質良好的影片被排除。觀看數、按讚數、留言數與發布天數主要用於排名與分數計算。

### 8.3 可選的成長門檻

後台可提供可開關的「成長門檻」：

- `min_views_per_day`，預設 250。
- `min_engagement_score`，預設 0.05。
- `max_age_days`，預設 90。

若啟用成長門檻，未達標者不一定完全淘汰，可以降低 ranking score。這比硬淘汰更適合 AI 這種快速變化領域。

## 9. 排名邏輯

### 9.1 顯示欄位名稱

英文 `engagement_score` 在 UI 中顯示為「參與度分數」。

### 9.2 基礎分數

```text
age_days = max(1, ceil((now - published_at) / 1 day))
engagement_score = like_count / max(view_count, 1)
fresh_engagement_score = engagement_score / age_days
view_velocity = view_count / age_days
comment_rate = comment_count / max(view_count, 1)
```

首頁 Top 20 預設排序：

```text
fresh_engagement_score DESC
```

也就是「按讚數除以點閱數，再除以上線天數」。

### 9.3 延伸排名分數

系統需保留進階綜合分數欄位：

```text
radar_score =
  0.35 * normalized_fresh_engagement_score +
  0.25 * normalized_view_velocity +
  0.10 * normalized_comment_signal +
  0.15 * topic_relevance_score +
  0.10 * tutorial_quality_score +
  0.05 * channel_trust_score +
  whitelist_boost - blacklist_penalty
```

第一版 UI 預設可先使用 `fresh_engagement_score`，但資料庫與 worker 應存下所有分數，讓未來改排序時不需重建資料。

### 9.4 留言數的使用方式

留言數不可直接視為品質保證。第一版只將留言數作為小權重訊號，並採用 cap 避免爭議影片、抽獎影片或吵架影片被過度加權。

建議：

```text
comment_signal = min(comment_rate, 0.03) / 0.03
```

## 10. 頻道可信度

### 10.1 推薦頻道

管理者可將頻道加入「推薦頻道」。UI 上可顯示「推薦頻道」，不要顯示「白名單頻道」。

推薦頻道功能：

- 排名加權。
- 後台可管理。
- 可輸入 channel ID、handle 或 URL。
- 可設定推薦理由。

### 10.2 排除頻道

管理者可將頻道加入黑名單。黑名單頻道的影片不顯示於公開網站，但 run log 需記錄排除原因。

### 10.3 頻道可信度分數

頻道分數可由以下訊號構成：

- 是否推薦頻道。
- 是否黑名單。
- 頻道訂閱數，若 API 可取得。
- 歷史內容被管理者保留/刪除比例。
- 歷史影片平均參與度。

第一版至少需支援推薦頻道 boost 與黑名單排除。

## 11. AI 分析能力

### 11.1 是否為教學影片

系統應使用 LLM 判斷影片是否屬於教學影片。輸入包括標題、描述、transcript 摘要、頻道資訊與 metadata。輸出需包含：

- `is_tutorial`: boolean
- `confidence`: 0 到 1
- `reason`: 繁體中文簡短理由
- `content_type`: tutorial / news / opinion / product_demo / marketing / other

### 11.2 入門難度判斷

第一版只標示「入門」。其餘影片不顯示難度標籤，資料庫可存 `normal`。

入門判準：

- 不要求數學背景。
- 不要求程式基礎。
- 名詞會解釋。
- 有步驟。
- 有範例。
- 明確面向初學者、零基礎、新手或入門者。

LLM 輸出需包含：

- `difficulty`: `beginner` 或 `normal`
- `reason`: 簡短理由，顯示於管理後台
- `confidence`: 0 到 1

管理者可在後台覆寫難度。

## 13. 搜尋與歷史影片

### 13.1 歷史資料

所有列入排名範圍的影片都保存到歷史資料庫，包括：

- 縮圖 URL。
- YouTube URL。
- 標題。
- 頻道。
- 發布日期。
- 觀看數。
- 按讚數。
- 留言數。
- 參與度分數。
- 主題標籤。
- 難易度標籤。
- 摘要。
- 學習目標。
- quiz。
- transcript 或 transcript 摘要。

### 13.2 搜尋體驗

使用者可用關鍵字搜尋歷史影片。搜尋應至少涵蓋：

- 標題。
- 頻道名稱。
- 摘要。
- 主題標籤。
- 關鍵概念。
- transcript 摘要。

### 13.3 AI 學習指引

當搜尋結果數量足夠時，系統可產生一段學習指引。例如：

> 如果您是 RAG 的初學者，建議先看 A 影片建立基本概念，再看 B 影片理解向量資料庫，最後依序觀看 C、D、E 完成小型實作。

第一版可在搜尋結果頁提供「產生學習順序建議」按鈕。為節省成本，不建議每次搜尋自動呼叫 LLM。

## 14. 詳情頁

詳情頁包含：

- 影片 metadata。
- 縮圖。
- 前往 YouTube 按鈕。
- 完整摘要，建議 500 到 800 字。
- 適合對象。
- 學習目標。
- 關鍵概念 tags。
- 入門難度判斷與理由，公開頁只顯示標籤，後台顯示理由。
- 3 題單選測驗。
- 每題標準答案、解析與 evidence_text。公開頁在使用者作答後才顯示答案與解析。
- Transcript 摘要，不直接顯示完整逐字稿，避免頁面過長與版權替代風險。

## 15. 測驗功能

每支影片固定產生 3 題單選題：

1. 理解題。
2. 應用題。
3. 觀念辨識題。

每題需包含：

- 題目。
- 4 個選項。
- 正確答案。
- 答案解析。
- evidence_text，引用影片 transcript 的短片段。
- question_type。

第一版不儲存一般使用者作答結果。作答流程在前端本機狀態完成，重新整理後不保留。

## 16. 管理後台

第一版需要管理後台。

### 16.1 功能

- 多管理員登入。
- 角色權限。
- 主題管理。
- 關鍵字與排除關鍵字管理。
- 地區、語言、發布時間範圍設定。
- 最低觀看數、參與度分數、每日抓取數量設定。
- LLM provider、API key、模型、fallback 模型設定。
- 推薦頻道與黑名單頻道管理。
- 內容新增、刪除、編輯、排序、置頂。
- Run schedule 管理。
- Agent run log 查詢。
- AI 判斷理由查看與手動覆寫。

### 16.2 管理者角色

建議第一版支援：

- `owner`：可管理管理員、金鑰與所有設定。
- `admin`：可管理內容、主題、排程與頻道。
- `editor`：可管理內容但不能管理 API keys 與管理員。
- `viewer`：只能查看 run log 與設定。

## 17. 模型與 BYOK

### 17.1 BYOK 設計

管理者可輸入 API Key，系統加密後儲存在 PostgreSQL。加密金鑰不存資料庫，需放在雲端環境變數，例如 `APP_SECRET_KEY`。

支援 provider：

- OpenAI。
- Gemini。
- Anthropic Claude。
- OpenRouter。

### 17.2 模型清單驗證

管理者輸入 API key 後，系統應：

1. 呼叫 provider 的 model list endpoint。
2. 驗證 key 是否可用。
3. 取得模型清單。
4. 讓管理者選擇主要模型與 fallback 模型。
5. 將驗證結果、時間與錯誤訊息記錄到後台。

### 17.3 Fallback

每個 LLM 任務可設定 fallback chain：

```text
primary_model -> fallback_model_1 -> fallback_model_2 -> fail
```

每次 fallback 都需記錄在 `llm_call_logs`。

## 18. 摘要與引用方式

### 18.1 公開摘要長度

- 首頁短摘要：100 到 200 個中文字。
- 詳情頁完整摘要：500 到 800 個中文字。
- Transcript 摘要：300 到 500 個中文字。

### 18.2 避免替代原影片

公開頁不顯示完整 transcript，也不產生過長逐字內容重寫。摘要應以學習導覽為目的，並清楚提供「前往 YouTube」連結。

### 18.3 建議文案位置

每張卡片摘要順序：

1. 適合誰。
2. 短摘要。
3. 你會學到什麼。
4. 關鍵概念 tags。

## 19. 成功指標

MVP 成功標準：

- 每日排程成功率 >= 95%。
- 每次 run 可完成每個啟用主題的候選抓取、去重、評分、摘要與 Top 20 產生。
- 影片重複率低於 5%。
- AI 輸出 JSON schema 成功解析率 >= 98%。
- 管理後台可修改主要參數並影響下一次 run。
- 搜尋結果可在 1 秒內回傳常見查詢結果，資料量小於 5 萬筆時。
- 手機版首頁可正常瀏覽。

## 20. 主要風險

| 風險 | 說明 | 緩解策略 |
|---|---|---|
| YouTube quota | 每日搜尋與 videos.list 有 quota 限制 | 每主題查詢數控制、去重、快取、run log 顯示 quota 用量 |
| 字幕不可用 | 無字幕影片不處理，可能漏掉好影片 | 第一版接受此限制，未來再加 Whisper |
| LLM 成本 | 摘要、分類、測驗會消耗 token | 只對入選候選影片摘要；快取 transcript 與 LLM 結果 |
| AI 誤判難度 | LLM 可能錯判入門程度 | 儲存理由與信心分數，允許管理者覆寫 |
| 免費雲端限制 | 免費 DB 容量與 worker 時間有限 | 壓縮 transcript、設定 retention、提供付費升級路線 |
| 內容品質不穩 | 高參與度不等於高品質 | LLM 教學判斷、推薦頻道、黑名單、管理者手動調整 |
